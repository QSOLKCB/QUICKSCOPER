# QUICKSCOPER v0.2.0 implementation notes

The opening brief asks for the feel of fast scope-and-shoot gameplay in a small, offline, single-player game using native browser technologies. The initial sketch had no executable HTML file and contained invalid shader assignment, incomplete camera matrices, mismatched buffer sizes, and unbounded timing. The implementation replaces those stubs with a coherent game while preserving the brief verbatim.

The simulation uses 120 Hz ticks. Rendering is independent, elapsed frame backlog is limited to 100 ms, and a large gap never becomes one giant movement step. Paused states consume no game time. Gameplay randomness comes from a per-run seed; visual effects and sound noise do not change gameplay RNG state. Practice bots retain movement around spawn anchors. Circuit bots choose close-range retreat, mid-range strafing and long-range approach. When occluded, they share a cached cardinal flow field around collision geometry. Tactical decisions run at 5 Hz, while movement remains at 120 Hz; firing always rechecks muzzle visibility. Surviving limb hits interrupt a charge and trigger a short evasive burst. Bots visibly charge for 1.15 seconds before an attack, require line of sight, and are less likely to hit moving or sprinting players.

The renderer batches static, flat-shaded box geometry into one GPU buffer and updates reusable typed meshes and separate persistent GPU buffers for bots and rifle parts. Unit-cube vertices are expanded once, then transformed directly into those arrays. Data dust uses one additive point vertex per particle, versus the previous 36 vertices per fragment cube; depth testing still hides dust behind cover. Particle counts are bounded and objects recycled. Effect lists compact in place, and DOM HUD updates are limited to 20 Hz. Perspective and view matrices are column-major. The same world box dimensions drive rendering, movement collision, and ray occlusion. Bot rays are transformed into the model's local orientation before testing hitboxes. Limb geometry is deliberately forgiving; the central torso/head regions drive single-shot eliminations.

The viewmodel uses a separate depth pass. Canvas 2D draws the circular scope mask, fine reticle, timing arc, hitmarker, damage vignette, and transient score labels. The DOM provides menus and status. Reduced motion removes camera bob and muzzle flashes, reduces fragments, and replaces damage vignette flashes with a border. Render resolution is capped for high-DPI screens.

WebGL 2 is preferred, with WebGL 1 fallback using the same basic shaders. There is no WebGPU path: a second renderer would add complexity without helping this small scene. Everything ships as readable ES modules. Web Audio is resumed from pointer gestures; controller-only starts may remain suspended under browser autoplay policy and uses synthesized noise and oscillators. The sound graph has a master volume, a separate music gain and disposable voices. An original 108 BPM score combines Euclidean pulse trains, modular scale degrees and equal-tempered pitch. A 120 ms audio-clock lookahead is serviced by the existing frame loop; no timers are added. Pause stops scheduled music voices, stalled frames skip backlog, and suspended contexts cannot queue a burst of unheard effects.

Offline installation is atomic: all runtime files must cache successfully before the new worker becomes active. Each cache includes the registration scope, so other QSOL games on the same Pages origin are unaffected. Existing games finish on their current cache; updates wait for old tabs to close. Relative paths support both a root-mounted local server and the GitHub repository path.

The cloud preview environment may not expose WebGL. CI therefore checks rendered pixels and graphics errors in Chromium using software rendering, alongside input/lifecycle/offline checks. Real GPU performance and subjective mouse feel still benefit from human playtesting.

The Xbox profile consumes only the W3C standard Gamepad mapping. Radial deadzones preserve partial movement, a curved look response improves fine aim, and trigger hysteresis/edges preserve one-pull firing. Reconnect, focus loss, pause, restart and respawn require neutral controls. Mouse capture is required only in the mouse profile. Controller sampling is once per rendered frame; analog look applies per fixed tick, and jump edges persist until consumed by a tick.

The trigger buffer is separate from `shoot()`: it can defer a press for at most 180 ms, but never bypasses the bolt or reload. Scoped shots wait for 150 ms of continuous aim. The final 150 ms of the bolt cycle overlaps the scope raise. Aim release and lifecycle resets cancel queued input. Collateral tracing gathers one nearest region per living bot, sorts by distance, and discards all intersections at or behind the nearest solid. Hit statistics count successful rounds separately from targets; each kill still extends the existing chain, with an additional fixed multi-kill bonus.

A local Node CPU microbenchmark on 2026-10-29 built 128 identical rotated boxes per frame: median 0.046 ms with reusable typed buffers versus 1.434 ms for the prior array-based builder including upload conversion (five measured batches after warm-up). The resulting Float32 vertices matched exactly. This isolates mesh generation; it is not an FPS claim. Run `npm run benchmark` for the current implementation, or pass an older renderer module exporting `Mesh` to compare. Browser/GPU cost and controller feel vary by device.

Input mapping references: [W3C Gamepad](https://www.w3.org/TR/gamepad/). Audio timing references: [Web Audio](https://www.w3.org/TR/webaudio/). Browser testing uses an injected controller fixture and test-only module instrumentation, without shipping debug globals. This checks mapping and lifecycle, not Bluetooth/USB hardware.

Next tuning should be based on play: scope timing, hip spread, bot placement, encounter density, and scoring. Keep the scope-to-shot rhythm central; avoid engine/framework migration or unnecessary service integrations.
